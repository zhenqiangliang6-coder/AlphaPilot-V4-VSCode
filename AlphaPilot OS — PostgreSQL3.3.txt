🧠 AlphaPilot OS — PostgreSQL 完整表结构（专业版）
1. 用户层（User Memory）
用于记住开发者偏好、风格、模型选择习惯。

sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    external_id TEXT UNIQUE,              -- VSCode/GitHub 用户标识
    name TEXT,
    preferences JSONB DEFAULT '{}'::jsonb, -- 语言偏好、解释风格、模型偏好
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
2. 项目层（Project Memory）
用于记住项目结构、技术栈、规范、约定。

sql
CREATE TABLE projects (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    name TEXT,
    root_path TEXT,                       -- 本地路径或仓库路径
    repo_url TEXT,
    tech_stack JSONB DEFAULT '{}'::jsonb, -- Python + FastAPI + React
    metadata JSONB DEFAULT '{}'::jsonb,   -- 代码规范、目录约定
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
3. 任务层（Task Memory）
用于记录每一次 AI 任务的完整生命周期。

sql
CREATE TABLE tasks (
    id UUID PRIMARY KEY,                  -- 直接用你的 task_id
    user_id INTEGER REFERENCES users(id),
    project_id INTEGER REFERENCES projects(id),
    source TEXT,                          -- react-webview / api / cli
    model TEXT,
    prompt TEXT,
    status TEXT,                          -- pending / running / done / failed
    result_summary TEXT,                  -- LLM 生成的任务摘要
    created_at TIMESTAMP DEFAULT NOW(),
    finished_at TIMESTAMP
);
4. 执行链层（Step Memory）
记录 analyze / plan / write / refine / test / fix / doc / docstring 的结构化输出。

sql
CREATE TABLE task_steps (
    id SERIAL PRIMARY KEY,
    task_id UUID REFERENCES tasks(id),
    step_type TEXT,                       -- analyze / plan / write ...
    status TEXT,
    input JSONB,
    output JSONB,                         -- 结构化 JSON（非常宝贵）
    created_at TIMESTAMP DEFAULT NOW(),
    finished_at TIMESTAMP
);
5. FileOps 层（FileOps Memory）
记录每一次文件创建/更新/删除的行为。

sql
CREATE TABLE task_file_ops (
    id SERIAL PRIMARY KEY,
    task_id UUID REFERENCES tasks(id),
    step_id INTEGER REFERENCES task_steps(id),
    op TEXT,                              -- create / update / delete
    path TEXT,
    role TEXT,                            -- main / test / doc / config / meta
    reason TEXT,
    from_step TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);
6. 文件层（File Memory）
记录项目中每个文件的“身份”。

sql
CREATE TABLE files (
    id SERIAL PRIMARY KEY,
    project_id INTEGER REFERENCES projects(id),
    path TEXT,
    current_version_id INTEGER,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
7. 文件版本层（Version Memory）
记录每次 FileOps 后文件的内容（支持回滚、历史查看）。

sql
CREATE TABLE file_versions (
    id SERIAL PRIMARY KEY,
    file_id INTEGER REFERENCES files(id),
    task_id UUID REFERENCES tasks(id),
    step_id INTEGER REFERENCES task_steps(id),
    content TEXT,                         -- 可压缩
    hash TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);
8. 长期记忆层（Long-term Memory）
用于存储 AI 的“知识”：偏好、规则、总结、模式。

sql
CREATE TABLE memories (
    id SERIAL PRIMARY KEY,
    owner_type TEXT,                      -- user / project / task
    owner_id INTEGER,
    memory_type TEXT,                     -- preference / rule / summary / pattern
    content TEXT,                         -- 自然语言记忆
    importance INTEGER DEFAULT 1,         -- 1-5
    created_at TIMESTAMP DEFAULT NOW()
);
9. 语义记忆层（Semantic Memory）
用于代码搜索、文档搜索、上下文注入（pgvector）。

sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE embeddings (
    id SERIAL PRIMARY KEY,
    owner_type TEXT,                      -- file / doc / memory / task
    owner_id INTEGER,
    vector VECTOR(1536),                  -- Qwen embedding 维度
    metadata JSONB,
    created_at TIMESTAMP DEFAULT NOW()
);

🔥 第三部分：Worker 如何读取记忆并注入 prompt？
流程是：

Worker 拉到任务

Node API 在发送任务给 Worker 前，调用 Memory Service：

查项目记忆

查用户偏好

查最近相关任务

查语义记忆（embedding）

把这些打包成：

json
{
  "system_context": "...",
  "project_context": "...",
  "memory_context": "...",
  "semantic_context": "..."
}
Worker 把这些注入到 prompt 的 system 部分

这样 Worker 就有“长期记忆”了。
