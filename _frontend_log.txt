### 1. 代码整体结构

本项目采用微服务架构，文件结构按服务边界划分，根目录下包含 `backend` (Python), `middleware` (Node.js), `vscode-ext` (TypeScript), `infra` (Docker) 四个核心目录。

#### 1.1 Python 智能后端 (`backend/`)
- **`app/main.py`**: FastAPI 应用入口，定义路由挂载、生命周期事件（启动/关闭）及全局异常处理。
- **`app/api/routes.py`**: 定义 `/chat/stream` 和 `/health` 接口，处理请求验证与响应流构建。

- **`src/proxy/load-balancer.ts`**: 实现简单的轮询或最少连接数策略，将请求分发至多个 Python 后端实例（预留扩展性）。

- **`src/types/interfaces.ts`**: 定义内部通信协议类型，确保前后端数据结构一致。

#### 1.3 VS Code 前端插件 (`vscode-ext/`)

### 2. 每个函数的职责

#### Python Backend
- **`stream_chat_response(prompt: str, session_id: str) -> AsyncGenerator`**: 
  - 职责：协调上下文管理器获取历史，调用 Qwen 客户端发起流式请求，逐块 yield 响应数据，并在发生错误时 yield 错误标记。
- **`manage_context(session_id: str, new_msg: dict) -> List[dict]`**: 
  - 职责：从 Redis 读取历史，追加新消息，若总 Token 数超过阈值则移除最早的消息，最后将更新后的列表写回 Redis。
- **`call_qwen_api(messages: List[dict]) -> AsyncIterator[str]`**: 
  - 职责：构造 HTTP 请求头，发送 POST 请求至 Qwen  endpoint，解析 SSE (Server-Sent Events) 流，提取 content 字段并抛出网络异常。

#### Node.js Middleware
- **`handleWebSocketConnection(ws: WebSocket) -> void`**: 
  - 职责：建立连接时生成唯一连接 ID，注册消息监听器；收到消息时透传至 Python 后端；收到后端响应时转发给 VS Code 插件。
- **`heartbeatMonitor() -> void`**: 
  - 职责：定时向所有活跃连接发送 Ping 包，若 N 次未收到 Pong 则主动断开连接并清理资源。
- **`forwardRequest(payload: any) -> Promise<any>`**: 
  - 职责：根据负载均衡策略选择后端实例地址，发起 HTTP/WebSocket 请求，处理超时与重试逻辑。

#### VS Code Extension
- **`sendCommandToMiddleware(command: string, context: string) -> void`**: 
  - 职责：序列化用户指令与编辑器上下文，通过 WebSocket 发送至中间件，并触发 UI 更新以显示“思考中”状态。
- **`renderStreamChunk(chunk: string) -> void`**: 
  - 职责：在 Webview 中安全地追加文本内容，处理 Markdown 渲染逻辑，保持滚动条在底部。
- **`captureActiveEditorContext() -> string | null`**: 
  - 职责：检查是否有活动编辑器，若有则获取选中文本或全文，进行脱敏或截断处理后返回。

### 5. 需要注意的边界情况

1.  **API 限流与降级**: 当 Qwen API 返回 429 状态码时，后端不应直接崩溃，而应捕获异常，向客户端返回友好的“服务繁忙”提示，并在日志中记录以便后续分析。需实现指数退避重试（如 1s, 2s, 4s），最多重试 3 次。
2.  **网络断连重连**: 免费云资源网络不稳定。Node.js 中间件需具备自动重连 Python 后端的能力；VS Code 插件需在 WebSocket 断开时提示用户“正在重连..."，并在重连成功后自动恢复会话状态（通过 SessionID）。
3.  **内存溢出保护**: 必须严格实施 Token 计数和滑动窗口机制。若单条用户输入过长（超过模型上限），需在发送前进行截断并提示用户“输入过长，已自动截断”。
4.  **并发会话隔离**: Redis Key 必须严格绑定 `session_id`，防止多用户或多标签页之间的上下文混淆。在分布式部署下，需确保 Redis 连接的线程安全性。
5.  **冷启动延迟**: 针对免费云资源的休眠机制，Node.js 中间件可配置一个轻量级的“保活”定时任务（如每 14 分钟访问一次自身健康检查接口），或由 VS Code 插件在用户打开插件时发送预热请求。
6.  **敏感信息泄露**: 严禁在日志中打印完整的 `API_KEY` 或用户代码中的敏感硬编码密钥。所有日志输出需经过脱敏处理。

}

throw lastError || new Error('Operation failed after retries'); }

export class SocketClient { private socket: WebSocket | null = null; private reconnectTimer: NodeJS.Timeout | null = null; private readonly url: string;

constructor(middlewareUrl: string) { this.url = middlewareUrl.replace('http', 'ws'); }

connect(onMessage: (msg: ChatMessage) => void, onError: (err: any) => void) { if (this.socket && this.socket.readyState === WebSocket.OPEN) { return; }

try { this.socket = new WebSocket(this.url); this.socket.onopen = () => { console.log('Connected to AlphaPilot Middleware'); if (this.reconnectTimer) { clearTimeout(this.reconnectTimer); this.reconnectTimer = null; } }; this.socket.onmessage = (event) => { const data = event.data; // Handle SSE-like format or raw JSON if (typeof data === 'string' && data.startsWith('data: ')) { try { const jsonStr = data.substring(6); const msg: ChatMessage = JSON.parse(jsonStr); onMessage(msg); } catch (e) { console.error('Failed to parse message', e); } } else { try { const msg: ChatMessage = JSON.parse(data); onMessage(msg); } catch (e) { console.error('Failed to parse raw JSON', e); } } }; this.socket.onerror = (err) => { console.error('Socket error', err); onError(err); }; this.socket.onclose = () => { console.log('Socket closed, attempting reconnect...'); this.scheduleReconnect(onMessage, onError); }; } catch (error) { console.error('Connection failed', error); this.scheduleReconnect(onMessage, onError); }
}

send(payload: any) { if (this.socket && this.socket.readyState === WebSocket.OPEN) { this.socket.send(JSON.stringify(payload)); } else { vscode.window.showErrorMessage('Not connected to AlphaPilot service.'); } }

private scheduleReconnect(onMessage: any, onError: any) { if (this.reconnectTimer) return; this.reconnectTimer = setTimeout(() => { this.connect(onMessage, onError); }, 3000); }

disconnect() { if (this.socket) { this.socket.close(); this.socket = null; } if (this.reconnectTimer) { clearTimeout(this.reconnectTimer); this.reconnectTimer = null; } } }

DOC: docs/architecture.md
AlphaPilot OS Architecture Documentation
Overview
AlphaPilot is a distributed AI coding assistant designed for VS Code, utilizing a microservices architecture to ensure scalability and deployability on free cloud tiers.

Components
1. Backend (Python/FastAPI)
Role: Core intelligence. Handles LLM interaction (Qwen API) and state management.
Tech Stack: FastAPI, Uvicorn, Redis, HTTPX.
Key Features:
Asynchronous streaming responses (SSE).
Context window management using sliding window algorithm in Redis.
Robust retry logic for external API calls.
2. Middleware (Node.js)
Role: Communication bridge and load balancer.
Tech Stack: Express, WS (WebSocket), TypeScript.
Key Features:
Maintains persistent WebSocket connections with VS Code clients.
Routes requests to available Python backend instances.
Handles connection resilience and heartbeat monitoring.
3. VS Code Extension (TypeScript)
Role: User Interface.
Tech Stack: VS Code API, Webviews.
Key Features:
Captures editor context (selected code).
Renders streaming markdown responses in a dedicated panel.
Manages reconnection logic transparently.
4. Infrastructure (Docker)
Role: Orchestration.
Components:
docker-compose.yml: Defines the service topology.
Redis: Stateful storage for conversation history.
Data Flow
User types in VS Code -> Extension captures context.
Extension sends JSON via WebSocket to Middleware.
Middleware forwards HTTP request to Backend.
Backend retrieves history from Redis, calls Qwen API.
Qwen streams tokens -> Backend yields SSE events.
Middleware relays SSE events to Extension.
Extension renders text in Webview.
Backend updates Redis with new turn.
Deployment
The system is designed to be deployed on platforms like Render, Railway, or Fly.io using the provided docker-compose.yml (adapted for single container or separate services) and .env configuration.
