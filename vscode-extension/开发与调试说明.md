# AlphaPilot Copilot VS Code 扩展开发与调试全流程说明

## 项目简介
AlphaPilot Copilot 是一个 VS Code 扩展，旨在为开发者提供 AI 驱动的代码分析、注释、重构、审查和自动生成补丁等能力。扩展通过侧边栏 UI 与用户交互，并调用后端 ModelRouter 服务实现智能化操作。

## 主要开发内容
- 实现了侧边栏 Webview（AlphaPilotSidebarProvider），支持模型选择、任务选择、补丁预览与应用、日志输出等功能。
- 注册了命令（alphapilot-copilot.run、alphapilot-copilot.runTask、alphapilot-copilot.previewPatch），支持从命令面板和侧边栏触发核心功能。
- 通过 patchManager 统一处理多文件补丁的预览与应用。
- 通过 modelRouterClient 调用后端 AI 服务。
- 完善了 package.json 的 contributes、activationEvents、views、commands 等配置，确保扩展能在侧边栏正确显示。

## 本地开发与调试流程
1. **依赖安装与编译**
   - 运行 `npm install` 安装依赖。
   - 运行 `npm run watch` 或 `npm run compile` 进行 TypeScript 编译。
2. **启动扩展开发主机**
   - 在 VS Code 主窗口按 F5，或点击“运行和调试”->“启动扩展”。
   - 会弹出一个新的 Extension Development Host 窗口。
   - 在新窗口左侧活动栏点击“AlphaPilot”图标，即可看到扩展 UI。
3. **常见问题排查**
   - 若 UI 显示“没有可提供视图数据的已注册数据提供程序”，请检查 package.json 的 views、viewType、activationEvents 配置与代码一致。
   - 若 UI 空白或功能异常，可在 sidebar.ts 的 getHtml 方法中返回简单 HTML 验证。
   - 若扩展未激活，可在 activate 函数内加 `vscode.window.showInformationMessage` 调试。

## 发布到 VS Code 扩展市场
1. 注册 Microsoft 账号并创建 Azure DevOps 组织。
2. 安装发布工具：`npm install -g vsce`
3. 生成 Personal Access Token（PAT），用于发布扩展。
4. 在项目根目录运行 `vsce package` 打包扩展。
5. 运行 `vsce publish` 发布扩展到市场。
6. 审核通过后即可在市场搜索、下载和安装。

## 关键文件说明
- `src/extension.ts`：扩展主入口，注册命令与侧边栏。
- `src/sidebar.ts`：侧边栏 Webview 逻辑与 UI 渲染。
- `src/modelRouterClient.ts`：与后端 AI 服务交互。
- `src/patchManager.ts`：补丁预览与应用。
- `package.json`：扩展元数据与 VS Code 配置。

## 典型问题与解决
删除项目下的 node_modules 和 out 目录，重新 npm install
- UI 无法显示：检查 viewType、id 配置一致性，确认 getHtml 返回有效 HTML。
- 扩展未激活：检查 activationEvents，建议加 onStartupFinished/onView 触发。
- 命令无效：确认 commands 注册与 contributes 配置一致。
1. 你的问题本质分析
扩展已激活，但侧边栏视图始终无法渲染（即 resolveWebviewView 没有被调用，或被调用但渲染失败）。
延长超时无效，说明不是单纯的启动慢或电脑性能问题。
package.json 配置已修正，id、viewType、activationEvents 都一致。
getHtml 返回简单 HTML 也无效，说明不是 HTML 代码本身问题。
没有明显报错，但 VS Code 一直提示“没有可提供视图数据的已注册数据提供程序”。
2. 可能的根本原因
A. VS Code/Node 环境异常
VS Code 版本过旧或过新，和扩展开发依赖不兼容。
Node.js 版本和 TypeScript 编译产物不兼容。
VS Code 安装损坏或缓存异常。
B. 依赖未正确安装或编译
node_modules 缺失或损坏，导致依赖包无法加载。
TypeScript 编译未生成 extension.js 或 sidebar.js 等产物。
package.json main 字段指向的入口文件不存在或有语法错误。
C. 代码逻辑问题
activate 函数执行异常（如同步死循环、阻塞、未捕获异常）。
AlphaPilotSidebarProvider 构造或注册逻辑有 bug，导致 resolveWebviewView 没有被正确注册。
侧边栏 viewType 注册和实际代码不一致（已排查过）。
D. VS Code 扩展开发主机 bug
有时 VS Code 的 Extension Development Host 会出现缓存或进程僵死问题，需彻底重启主 VS Code 和所有开发主机窗口。
E. 系统/权限/杀毒软件影响
某些杀毒软件、系统权限设置会阻止 VS Code 子进程或 Webview 加载。
3. 逐步排查与解决建议
1. 环境彻底清理与重装
关闭所有 VS Code 窗口，彻底退出 VS Code。
删除项目下的 node_modules 和 out 目录，重新 npm install。
确认 VS Code 版本为官方稳定版，建议 1.80+。
如有条件，升级 Node.js 至 LTS 版本（如 18.x 或 20.x）。
2. 编译与产物检查
运行 npm run compile，确保 out/extension.js、out/sidebar.js 等文件都已生成。
检查 package.json 的 main 字段是否指向 out/extension.js，且该文件存在。
3. 极简代码测试
将 extension.ts 的 activate 函数内容全部注释，仅保留 vscode.window.showInformationMessage("激活")，看是否还会卡住。
如果能正常弹窗且无超时，再逐步恢复注册侧边栏的代码，定位是哪一行导致阻塞。
4. 新建空白扩展对比
用 yo code 新建一个最简单的侧边栏扩展，确认你的 VS Code 环境能否跑通最基础的 Webview。
如果新扩展能正常显示 UI，说明你的项目代码有问题；如果新扩展也不行，说明是环境或 VS Code 问题。
5. 检查系统与权限
关闭所有杀毒软件、管控软件，确保 VS Code 有完整读写和网络权限。
用管理员权限启动 VS Code 试试。
6. 查看调试控制台和日志
在扩展开发主机窗口，打开“帮助”->“切换开发人员工具”，查看 Console 是否有红色报错。
查看“输出”面板中“Extension Host”日志
